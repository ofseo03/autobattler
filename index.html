자료구조 3주차 — 연결 리스트와 스택·큐

강의 노트 · 2026-09-14 · 수정 중

1. 지난 시간 복습

배열은 인덱스로 O(1) 접근이 가능하지만 중간 삽입·삭제에 O(n)이 든다. 이번 주에는 삽입·삭제가 잦은 상황을 위해 노드를 포인터로 잇는 연결 리스트를 다루고, 그 위에 스택과 큐를 구현한다. 시험 범위에는 단일·이중 연결 리스트의 삽입/삭제 코드와 시간 복잡도 표가 포함된다.

2. 단일 연결 리스트

각 노드는 데이터와 다음 노드를 가리키는 참조(next)를 갖는다. 리스트 자체는 첫 노드(head)만 기억하면 되며, 마지막 노드의 next는 null이다. 길이를 자주 묻는다면 별도의 size 필드를 유지하는 편이 낫다.

class Node:
    def __init__(self, data, next=None):
        self.data = data
        self.next = next

def insert_front(head, data):
    return Node(data, head)          # O(1)

def delete_after(node):
    if node.next is not None:
        node.next = node.next.next   # O(1)

맨 앞 삽입은 O(1)이지만 맨 뒤 삽입은 tail 참조가 없으면 끝까지 순회해야 하므로 O(n)이다. 실무에서는 tail 참조를 함께 두거나 이중 연결 리스트를 사용한다.

연산배열단일 연결 리스트이중 연결 리스트
인덱스 접근O(1)O(n)O(n)
맨 앞 삽입O(n)O(1)O(1)
맨 뒤 삽입O(1)*O(n) / O(1) tailO(1)
중간 삭제O(n)O(1)**O(1)**

* 여유 공간이 있을 때 (동적 배열은 상각 O(1))   ** 해당 노드를 이미 찾았다고 가정

3. 이중 연결 리스트

prev 참조를 추가하면 어느 노드에서든 양방향으로 이동할 수 있고, 노드 자신만 알아도 삭제가 가능하다. 대신 노드당 참조 하나만큼 메모리가 늘고, 삽입·삭제 시 갱신할 참조가 4개로 늘어 실수하기 쉽다. 경계 조건(head·tail 삭제)을 줄이기 위해 더미 헤드/테일(sentinel) 노드를 두는 기법을 기억하자.

  • 삽입 순서: 새 노드의 prev/next 먼저 설정 → 이웃 노드의 참조 갱신
  • 삭제 순서: 이웃 노드의 참조를 서로 연결 → 삭제 노드 참조 해제
  • 센티널을 쓰면 빈 리스트 특수 처리가 사라진다

4. 스택 (Stack)

LIFO. push/pop/peek 이 전부 O(1)이어야 한다. 배열로 구현하면 맨 뒤에서만 넣고 빼고, 연결 리스트로 구현하면 head 에서만 넣고 뺀다. 대표 응용: 괄호 짝 검사, 후위 표기식 계산, 함수 호출 스택, 실행 취소(undo).

def balanced(s):
    stack = []
    pair = {')': '(', ']': '[', '}': '{'}
    for ch in s:
        if ch in '([{':
            stack.append(ch)
        elif ch in pair:
            if not stack or stack.pop() != pair[ch]:
                return False
    return not stack

5. 큐 (Queue)

FIFO. 배열로 단순 구현하면 dequeue 가 O(n)이 되므로 원형 큐(circular queue)로 front/rear 인덱스를 모듈러 연산으로 돌린다. 연결 리스트 구현은 head 에서 빼고 tail 에 넣는다. 덱(deque)은 양 끝 모두에서 O(1) 삽입·삭제가 되는 자료구조로, 파이썬 collections.deque 가 이중 연결 리스트 기반이다.

원형 큐에서 "가득 참"과 "비어 있음"을 구분하는 방법은 두 가지다. (1) 한 칸을 비워 두고 (rear+1)%N == front 를 가득 참으로 본다. (2) size 카운터를 따로 유지한다. 시험에서는 (1)을 기준으로 출제된다.

부록 A. 자주 하는 실수

  • 삭제 시 순서를 잘못해 남은 리스트를 잃어버림 (next 를 먼저 끊는 실수)
  • 빈 리스트에서 pop/dequeue 예외 처리 누락
  • 원형 큐 인덱스에 모듈러 연산을 빼먹어 범위 초과
  • 이중 연결 리스트에서 prev 갱신 누락 — 역방향 순회로 검증할 것

부록 B. 복잡도 요약

스택·큐의 모든 기본 연산은 O(1), 연결 리스트 탐색은 O(n), 정렬된 연결 리스트라도 이진 탐색은 불가하다(임의 접근이 없으므로). 공간 복잡도는 노드 수에 비례하며, 참조 필드만큼 배열보다 상수 배 더 쓴다.
